## 1. Что это за проект (в двух абзацах)

Мы автоматизируем **поиск постоянной квартиры в Берлине для одного человека**.
Человек сейчас временно живёт в общежитии, трудового дохода нет, подано
заявление на Bürgergeld (пособие; жильё в этом случае оплачивает Jobcenter),
параллельно оформляется WBS (право на социальное жильё). Обычный рынок
(«покажите справку о зарплате») для него практически закрыт, поэтому
**главный канал — WBS-квартиры и социальное жильё**, в первую очередь от
шести городских жилищных компаний Берлина.

Система каждые несколько минут обходит разные источники объявлений,
вытаскивает из них структурированные данные (адрес, площадь, комнаты,
Kaltmiete / Nebenkosten / Heizkosten / Warmmiete, WBS да/нет и т.д.),
отфильтровывает явно неподходящее, помечает приоритет и складывает всё в
**Google-таблицу** и в **базу Supabase**. Скорость важна: хорошая квартира
в Берлине уходит примерно за 40 минут, поэтому цель — узнавать о ней первыми.
Автоматическая подача заявок — будущий этап, сейчас его нет.

**Текущий режим — спокойный мониторинг, а не срочная аренда.** Интересны и
квартиры с заселением в горизонте до ~6 месяцев (поздняя дата заселения,
листы ожидания кооперативов).

## 2. Критерии: какая квартира нам нужна

| Параметр | Значение |
|---|---|
| Тип | Отдельная квартира (не WG-комната): 1–2 комнаты, студия, небольшая квартира с кухней |
| Главный географический ориентир | **Boxhagener Platz** (Friedrichshain), рядом Ostkreuz |
| Радиус | **3,5 км** по прямой от Boxhagener Platz (фильтр); до 2 км — приоритет 🟢 |
| Районы | Friedrichshain, Mitte — в первую очередь; дальше Lichtenberg/Rummelsburg, Alt-Treptow, Kreuzberg, Neukölln — если попадают в радиус |
| Только Берлин | Бранденбург (Panketal, Fredersdorf и т.п.) отбрасывается |
| Цена (грубый фильтр) | Warmmiete ≤ 750 €, или Kaltmiete ≤ 600 €, если Warmmiete неизвестна |
| Лимит Jobcenter | Ориентир — Bruttokaltmiete (Kalt + Nebenkosten, без отопления) ~449 € для 1 человека по AV Wohnen, с надбавками выше. **Цифры меняются — перед использованием в логике проверять по официальным источникам.** |
| WBS | Основной фокус. Но квартира без WBS тоже интересна, если арендодатель принимает оплату через Jobcenter и не требует дохода |
| Дата заселения | Сейчас или в пределах ~6 месяцев |

Все эти значения сейчас живут в блоке `filters:` файла `sources.yaml`.

**Принцип фильтрации:** если у объявления поле неизвестно (например, не
удалось распарсить Warmmiete), по этому полю объявление **НЕ отсеивается**.
Лишняя строка в таблице лучше пропущенной квартиры.

**Про Jobcenter:** код и отчёты никогда не должны утверждать, что Jobcenter
«точно оплатит» квартиру. Допустимые формулировки: «потенциально подходит»,
«нужно проверить соответствие лимитам», «нужна Zusicherung».

## 3. Источники объявлений

Источники разбиты на **группы**. Для каждой группы — **свой отдельный парсер**
(см. раздел 5 «Направление рефакторинга»). Причина разбиения — у сайтов
разная защита от ботов, разная структура данных и разная ценность для нас.

### Группа A — городские жилищные компании (landeseigene Wohnungsbaugesellschaften) ⭐ главный приоритет

Шесть компаний, принадлежащих земле Берлин. Именно у них основная масса
WBS-квартир и они не требуют зарплатных справок так жёстко, как частники.

| Компания | Идентификатор в коде |
|---|---|
| HOWOGE | `howoge` |
| degewo | `degewo` |
| WBM | `wbm` |
| GESOBAU | `gesobau` |
| Gewobag | `gewobag` |
| Stadt und Land | `stadtundland` |

- Парсятся **напрямую с сайтов компаний** (`landeseigene.py`, тип источника
  `type: company` в `sources.yaml`).
- Работает в облаке (GitHub Actions) — у этих сайтов нет жёсткого антибота.
- Дополнительно — общий портал **inberlinwohnen.de** (агрегатор всех шести).
  Он идёт в списке **после** компаний и используется как **контроль полноты и
  замер задержки**: если квартира уже найдена на сайте компании, второй строки
  не будет, только отметка времени в `timing.json`. Так мы видим, насколько
  портал отстаёт от первоисточников.
- Владелец готов завести аккаунты на сайтах компаний, если это позволит
  получать только релевантные объявления (фильтры/подписки на сайте).

**Текущий этап для группы A:** только **сбор данных и оценка качества сбора**
(все ли объявления находятся, правильно ли парсятся поля). Обработка —
Jobcenter-оценка, сложные фильтры — отдельным следующим шагом.

### Группа B — жилищные кооперативы (Wohnungsbaugenossenschaften)

- **FriedrichsHeim eG** — два RSS-фида («для всех» и «только для членов»),
  подключены и проверены (`type: rss`).
- Другие кооперативы добавляются по одному. У многих — листы ожидания и
  членство; горизонт ~6 месяцев это допускает.
- В будущем — отдельный парсер для кооперативов.

### Группа C — Kleinanzeigen (бывш. eBay Kleinanzeigen)

- Сильная защита от ботов, **банит датацентровые IP** → запускается
  **только локально на компьютере владельца** (домашний IP), не в Actions.
- Уже есть рабочий скрипт на `nodriver` (браузерная автоматизация) —
  **он пока лежит не в этом репозитории**, а локально у владельца
  (`kleinanzeigen_monitor.py`, `sheets_sync.py`, `red_flags.py`).
  Его нужно перенести в репозиторий как отдельный парсер.
- При обнаружении капчи/блокировки скрипт **обязан остановиться целиком**
  (исключение `BlockDetected`), а не молча пропускать страницы.

### Группа D — крупные порталы: ImmoScout24, Immowelt (Immonet)

- Защита уровня DataDome/Imperva, банит датацентры → **только локально**,
  через настоящий браузер (Playwright/Chromium), интервал 30–45 минут
  с случайным сдвигом, не ровно.
- Прототип — `local/local_monitor.py` (+ `local/README-local.md`).
- Ценность ниже, чем у группы A (много объявлений с требованием дохода),
  но WBS-объявления и «Jobcenter willkommen» там встречаются.
- Immonet сейчас по сути часть Immowelt — отдельно парсить, скорее всего,
  не нужно (проверить перед работой).

### Группа E — социальные сети и прочее (планируется, не начато)

- **Facebook-группы** по аренде в Берлине (в т.ч. русскоязычные). Требуют
  логина, автоматизация рискованна → вероятно, полуручной режим или
  браузерная автоматизация локально. Особенно внимательно к мошенничеству.
- **Email-уведомления** от порталов: идея — раз в ~10 минут проверять папку
  почты и вытаскивать данные из писем (обходит антибот полностью).
- **Ручной ввод ссылок** владельцем — для источников без API/RSS/почты.
- Кандидаты на будущее: другие кооперативы, WG-Gesucht (только отдельные
  квартиры), сайты социальных служб и жилищных проектов.

## 4. Текущая архитектура (как есть сейчас)

```
                 ┌─────────────── ОБЛАКО: GitHub Actions ───────────────┐
sources.yaml ──► │ monitor.py  ──► landeseigene.py (группа A)            │
                 │             ──► RSS (группа B)                        │
                 │  geo.py: геокодинг + расстояние до Boxhagener Platz   │
                 └───────────────────────┬───────────────────────────────┘
                                         │
                 ┌──── ЛОКАЛЬНО: ПК владельца (Windows) ────┐
                 │ local/local_monitor.py  (группа D)        │
                 │ kleinanzeigen_monitor.py (группа C, пока  │
                 │   вне репозитория)                        │
                 └───────────────────────┬───────────────────┘
                                         ▼
                 Google Sheet «Поиск квартиры Берлин», вкладка «Объявления»
                 + Supabase: таблица public.listings
```

### Файлы в корне

| Файл | Назначение |
|---|---|
| `monitor.py` | Облачный монитор: обходит источники из `sources.yaml`, фильтрует, пишет в таблицу и базу |
| `landeseigene.py` | Парсеры шести городских компаний + inberlinwohnen.de |
| `geo.py` | Геокодинг адресов, расстояние до Boxhagener Platz |
| `sheets.py` | Запись в Google-таблицу через сервисный аккаунт |
| `db.py` | Запись в Supabase через REST (PostgREST), без лишних зависимостей |
| `sources.yaml` | Список источников и фильтры |
| `seen.json` | Какие объявления уже видели (дедупликация) |
| `timing.json` | Когда объявление впервые появилось в каком источнике (замер задержки портала) |
| `geocache.json` | Кэш геокодинга |
| `.github/workflows/monitor.yml` | Расписание |
| `local/` | Локальный монитор для порталов с антиботом |

### Как работает расписание

- Cron запускает workflow каждые 30 минут; один прогон крутится ~50 минут и
  проверяет источники каждые 3 минуты (`LOOP_MINUTES`, `CHECK_INTERVAL`).
  `concurrency` не даёт двум прогонам работать одновременно — получается
  почти непрерывный мониторинг.
- После каждой проверки бот коммитит `seen.json`, `timing.json`,
  `geocache.json` обратно в репозиторий (`[skip ci]`).
- Репозиторий **публичный** — ради бесплатных безлимитных минут Actions.

### Хранилище

- **Google-таблица** — основной интерфейс для человека. Вкладка «Объявления».
  Колонки соответствуют полям из раздела 6.
- **Supabase** — проект `wohnung-monitor`, таблица `public.listings`.
  Одна строка = одно объявление, уникальность по паре `(source, external_id)`,
  повторы игнорируются. Числа хранятся числами; `bruttokalt` считается
  базой автоматически (удобно фильтровать под лимит Jobcenter).
  Если база недоступна — скрипт пишет предупреждение и продолжает писать
  в таблицу (база не должна ломать основной поток).
- Колонки `listings`: `source, source_type, external_id, listing_key, link,
  title, company, address, district, postcode, housing_type, rooms, area_m2,
  kalt, neben, heiz, warm, wbs, jobcenter_note, distance_km, distance_src,
  priority, status, comment, published_at, red_flags, raw` (+ служебные
  `id`, `found_at`, `bruttokalt`).

### Секреты (GitHub Secrets / переменные окружения)

- `GOOGLE_SERVICE_ACCOUNT_JSON` (или локально `GOOGLE_SERVICE_ACCOUNT_FILE`)
- `SUPABASE_KEY` — секретный ключ (`sb_secret_…` / service_role)
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — не используются, Telegram
  выключен (`USE_TELEGRAM=false`). Владелец решил: пока всё только в таблицу.

## 5. Направление рефакторинга (куда мы идём)

Решение владельца: **старую общую архитектуру (один `monitor.py` на всё)
разбираем.** Строим **отдельный самостоятельный парсер на каждую группу
источников**:

1. **Парсер группы A** (шесть городских компаний) — делается первым.
   Этап 1: только сбор + отчёт о качестве (сколько объявлений нашли на каждом
   сайте, какие поля заполнены, где пусто/ошибки, сравнение с
   inberlinwohnen.de). Этап 2: обработка (фильтры, Jobcenter-оценка,
   приоритеты).
2. Парсер кооперативов (FriedrichsHeim eG и др.).
3. Парсер Kleinanzeigen (перенести локальный скрипт в репозиторий).
4. Парсер ImmoScout24 / Immowelt (локальный, браузерный).
5. Позже: почтовые уведомления, Facebook, ручной ввод ссылок.

Все парсеры пишут в **одно и то же хранилище** (таблица + Supabase) в
**едином формате записи** (раздел 6). Общий код (запись в таблицу/базу,
геокодинг, red flags, фильтры) — в общих модулях, а не копипастой в каждом
парсере.

Известные расхождения, которые стоит поправить при рефакторинге:

- `README.md` местами устарел (пишет «раз в 30 минут» и «Telegram» как
  основную цель — на деле проверка каждые 3 минуты, Telegram выключен).
- Модули `db.py` / `sheets.py` продублированы в `local/`.
- Локальный Kleinanzeigen-скрипт и `red_flags.py` пока вне репозитория.
- Состояние «что уже видели» хранится в JSON в репозитории; логичнее со
  временем перенести его в Supabase.

## 6. Единый формат объявления

Для каждого объявления, по возможности, извлекаем:

| Поле | Что записывать |
|---|---|
| Адрес / район | Максимально точно; район (Bezirk/Ortsteil), индекс |
| Ссылка | Прямая ссылка на объявление |
| Kaltmiete | € |
| Nebenkosten (Betriebskosten) | € |
| Heizkosten | € |
| Warmmiete | € |
| Площадь | м² |
| Комнаты | 1 / 1,5 / 2 … |
| WBS | Да / Нет / неизвестно; тип WBS (WBS 100/140/160/180, «besonderer Wohnbedarf»), если указан |
| Jobcenter | «потенциально» / неизвестно / нет — с пояснением |
| Расстояние | км до Boxhagener Platz (и источник координат) |
| Дата объявления | если есть |
| Дата заселения | Bezugsfrei ab |
| Контакт | телефон / email / форма |
| Статус | Найдено / написали / ответили / просмотр / отказ (ведёт человек) |
| Комментарий | важные детали + найденные red flags |

### Приоритет

- 🟢 — хороший вариант, стоит подаваться (в радиусе 2 км, проходит по цене, WBS или Jobcenter допускается)
- 🟡 — возможный, есть вопросы
- 🔴 — скорее не подходит (объяснить почему)

(В правилах проекта есть и шкала A–D, она соответствует той же логике:
A ≈ 🟢, B ≈ 🟡, C ≈ 🔴, D — мошенничество/не рассматривать.)

## 7. Red flags: помечаем, а не выкидываем

Решение по проекту: объявления с «опасными» словами **не удаляются**, а
помечаются в колонке «Комментарий» / поле `red_flags`. Два типа маркеров:

**Исключают Jobcenter-кейс:** Gehaltsnachweis, Einkommensnachweis,
Nettoeinkommen, unbefristeter Arbeitsvertrag, 3 Nettogehälter,
Mindesteinkommen, Bonität, Schufa, Bürgschaft, «keine Transferleistungen»,
«kein Bürgergeld» и т.п.

**Признаки мошенничества:** Kaution in bar, Vorkasse/Vorauskasse,
Reservierungsgebühr, Provision im Voraus, Überweisung vor Besichtigung.
Также подозрительны: цена сильно ниже рынка, нет адреса, давление «решить
сегодня», просьба прислать паспорт неизвестному человеку, деньги до
просмотра. Особенно актуально для Kleinanzeigen и Facebook.

Список живой — дополнять по мере того, что встречается.

## 8. Правила работы для Claude Code в этом репозитории

1. **Общайся по-русски.** Немецкие термины — с пояснением.
2. **Репозиторий публичный.** Никогда не коммить секреты, ключи, JSON
   сервисного аккаунта, `.env`, а также **личные данные** (адрес проживания,
   номера дел Jobcenter/WBS, телефон, паспортные данные). Секреты — только
   через GitHub Secrets / переменные окружения, не выводить их в лог и чат.
3. **Сайты с антиботом (Kleinanzeigen, ImmoScout24, Immowelt, Facebook) не
   запускать из GitHub Actions** — забанят IP и могут заблокировать аккаунт.
   Только локально, с человеческими интервалами и случайными паузами.
   Не запускать облачный и локальный мониторинг одного сайта одновременно.
4. **Не ломать основной поток.** Ошибка одного источника/базы не должна
   останавливать остальные (кроме `BlockDetected` — там стоп целиком).
5. **Лучше лишняя строка, чем пропущенная квартира** — неизвестные поля не
   отсекают объявление.
6. **Никаких автоматических откликов/заявок** без явного решения владельца.
   Когда дойдём до автоподачи — сообщения короткие, честные (дохода сейчас
   нет, Bürgergeld подан, оплата через Jobcenter после согласования),
   без выдуманного дохода.
7. **Не утверждать, что Jobcenter оплатит** конкретную квартиру.
8. Владелец — не профессиональный разработчик: предпочитает простые решения,
   минимум платных сервисов, пошаговые инструкции. Перед крупными
   изменениями архитектуры — коротко объяснить план по-русски.
9. Менять по одному источнику/группе за раз и проверять результат
   (ручной запуск workflow, в т.ч. `self_test=true`).

### Как проверить, что всё работает

- GitHub → Actions → «Wohnung Monitor» → **Run workflow**
  (галка `self_test` — пишет одну тестовую строку в таблицу и базу).
- Локальная часть — см. `local/README-local.md`.

## 9. Глоссарий (немецкий → по-русски)

| Термин | Значение |
|---|---|
| **WBS** (Wohnberechtigungsschein) | Справка о праве на социальное жильё; без неё WBS-квартиру не сдадут |
| **Sozialwohnung** | Социальная квартира с ограниченной арендной платой, обычно требует WBS |
| **landeseigene Wohnungsbaugesellschaften** | Городские (земельные) жилищные компании Берлина — наши шесть: HOWOGE, degewo, WBM, GESOBAU, Gewobag, Stadt und Land |
| **Wohnungsbaugenossenschaft (eG)** | Жилищный кооператив; часто нужно вступить (купить паи), есть листы ожидания |
| **Bürgergeld** | Базовое пособие; при нём расходы на жильё оплачивает Jobcenter в пределах лимитов |
| **Jobcenter** | Ведомство, которое выплачивает Bürgergeld и оплачивает жильё |
| **Zusicherung** | Предварительное согласие Jobcenter оплачивать конкретную квартиру — получать **до** подписания договора |
| **AV Wohnen** | Берлинское положение о допустимых расходах на жильё для получателей пособий (лимиты) |
| **Kaltmiete** | «Холодная» аренда — только за квартиру |
| **Nebenkosten / Betriebskosten** | Коммунальные расходы (без отопления): вода, мусор, уборка и т.п. |
| **Heizkosten** | Отопление |
| **Warmmiete** | Полная аренда = Kalt + Nebenkosten + Heizkosten |
| **Bruttokaltmiete** | Kalt + Nebenkosten, без отопления — именно её Jobcenter сравнивает с лимитом |
| **Bezugsfrei ab** | Свободна для заселения с даты |
| **Mietvertrag** | Договор аренды |
| **Kaution** | Залог (обычно до 3 Kaltmieten); платится после подписания договора, не до просмотра |
| **Schufa** | Кредитная история |
| **Gehaltsnachweis / Einkommensnachweis** | Справка о доходе / зарплате |
| **Mietübernahme durch das Jobcenter** | Оплата аренды Jobcenter'ом |
| **besonderer Wohnbedarf** | Особая жилищная потребность (например, проживание во временном жилье) — может давать приоритет по WBS |
| **Altbau** | Старый фонд (дома до ~1918 г.), типичен для Friedrichshain |
