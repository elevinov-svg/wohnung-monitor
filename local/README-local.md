# Локальный монитор (ImmoScout24 / Immowelt / Kleinanzeigen)

Этот скрипт запускается **на твоём компьютере**, не в облаке — потому что
эти сайты банят/капчат датацентровые IP (AWS, GitHub Actions и т.п.), а
твой домашний IP для них выглядит как обычный посетитель.

## Установка (один раз)

```bash
cd local
pip install -r requirements-local.txt
playwright install chromium
cp local_sources.example.yaml local_sources.yaml
```

Открой `local_sources.yaml` и вставь свои реальные ссылки на поиск —
см. комментарии внутри файла, как их получить.

Новые объявления пишутся в ту же Google-таблицу, что и облачный скрипт
(вкладка "Объявления"). Нужен тот же сервисный аккаунт, что настраивали
для облачной части (см. README.md в корне проекта, раздел "Google Sheets —
настройка") — просто используем тот же JSON-ключ здесь, локально.

Сохрани скачанный JSON-ключ сервисного аккаунта в файл рядом со скриптом,
например `local/service-account.json` (в `.gitignore`, если будешь класть
эту папку в Git — ключ никогда не должен попасть в публичный репозиторий).

Telegram пока не используем (см. README.md в корне) — если понадобится,
включается переменной `USE_TELEGRAM=true` + `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`.

## Разовый запуск (проверить, что работает)

**Linux/macOS:**
```bash
export GOOGLE_SERVICE_ACCOUNT_JSON="$(cat service-account.json)"
python3 local_monitor.py
```

**Windows (PowerShell) — проще указать путь к файлу:**
```powershell
$env:GOOGLE_SERVICE_ACCOUNT_FILE = "C:\путь\до\wohnung-monitor\local\service-account.json"
python local_monitor.py
```

## Поставить на расписание (раз в 30–45 минут)

Для этих сайтов я бы не делал интервал короче 30 минут и не делал его
идеально ровным (см. "Важно про антифрод" ниже) — раз в 30–45 минут с
небольшим случайным сдвигом безопаснее, чем ровно каждые 30:00.

### Linux/macOS — через cron

```bash
crontab -e
```

Добавить строку (пример — каждые 40 минут):

```
*/40 * * * * cd /полный/путь/до/wohnung-monitor/local && GOOGLE_SERVICE_ACCOUNT_JSON="$(cat service-account.json)" /usr/bin/python3 local_monitor.py >> monitor.log 2>&1
```

### Windows — через Task Scheduler

1. Открыть "Планировщик заданий" (Task Scheduler).
2. Создать задачу → Триггер: "Повторять каждые 40 минут", бессрочно.
3. Действие: запустить программу `python.exe` с аргументом
   `C:\путь\до\wohnung-monitor\local\local_monitor.py`,
   рабочая папка — `C:\путь\до\wohnung-monitor\local`.
4. Переменную окружения `GOOGLE_SERVICE_ACCOUNT_FILE` (путь к JSON-ключу)
   проще всего прописать не в самой задаче, а один раз в системных
   переменных среды Windows (Панель управления → Система → Переменные среды).

## Важно про антифрод — что это решает, а что нет

- **Решает:** IP-репутацию (домашний IP вместо датацентра) и то, что
  запросы идут через настоящий рендерящийся браузер (Playwright/Chromium),
  а не голый `requests` — JS-защиту типа "выполни код и получи токен"
  такой подход проходит нормально.
- **НЕ гарантирует:** более продвинутые системы (Imperva, DataDome,
  PerimeterX — такое часто стоит именно на крупных порталах) смотрят ещё
  и на поведенческие паттерны (движения мыши, тайминги), и headless-браузер
  всё равно можно вычислить статистически при частых заходах.
- Если через какое-то время сайт всё же начнёт показывать капчу именно
  этому скрипту — это не значит, что подход неверный, значит нужно
  снизить частоту и/или добавить более полную имитацию поведения
  (случайные прокрутки, паузы). Напиши, если дойдёт до этого — доработаем.
- Не запускай локальный и облачный мониторинг источников одного и того же
  сайта одновременно — session/cookies от одного забега не должны мешать
  другому.
